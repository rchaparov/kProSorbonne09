# Архитектурные принципы — TeamSpace / kProSorbonne09
# Команда: Сорбона 09

Обязательны при проектировании любого модуля.

---

## 1. Безопасность

- Никаких "лёгких" решений в угоду простоте
- Least Privilege — минимум привилегий для каждой роли
- Все пароли: bcrypt, не MD5/SHA1
- Cookie: httponly=True, samesite="lax"
- Секреты только через `.env` / Railway ENV variables, никогда не в коде

## 2. Роли и права доступа

- Три системные роли: admin, coordinator, member
- Роли захардкожены в коде — нельзя удалить через UI
- Проверка прав — через FastAPI dependency, не инлайн в роуте
- `can_write_to_project()` — всегда вызывать перед записью, не полагаться на UI

## 3. UI

- Только SVG иконки — никаких эмодзи в шаблонах
- Light theme — коллеги не используют тёмные темы
- Tailwind CDN — не npm build (для скорости MVP)
- Jinja2 SSR — не SPA (проще, быстрее запустить)

## 4. База данных

- Все timestamps в UTC
- FK с CASCADE там где логично (attachment → note, member → project)
- Файлы — bytea в PostgreSQL, лимит 10MB на файл
- Alembic для всех изменений схемы — никаких ручных ALTER TABLE

## 5. Общий принцип

**MVP — значит минимально, но правильно. Не быстро и криво, а быстро и надёжно.**
Скоупа два уровня: что делаем сейчас и что не делаем вообще.
Не добавлять функциональность "на будущее" без явного требования.
